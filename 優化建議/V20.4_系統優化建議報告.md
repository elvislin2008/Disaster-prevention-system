## 1.2 核心關鍵發現與規格脫節警示摘要

在 45 項建議中，有 5 大核心發現攸關系統在真實強震情境下的生死存亡，必須列為最急迫修復對象：

1. **午餐時段 12:00 vs 12:40 邊界脫節（OPT-05 / SPEC-02，P0）**：
   試算表排程截圖明確顯示上午時段為 `08:00-12:40`，但前端程式碼第 530 行以 `currentMinutes < 720` (12:00) 提早切換為下午 `pm1`。由於一二年級 `pm1` 為未在校，平日 12:00~12:40 用餐時間突發地震時，一二年級所有班級將被誤判為「不在校」而在系統中「幽靈化」，搜救與點名完全遺漏！規格書第 93 行亦需同步由 12:00 修正為 12:40。
2. **嚴重違背第七節鐵律 4：抽離待確認誤判為失蹤並染紅卡片（OPT-06 / SPEC-03，P0）**：
   規格書 Section 7 明定「抽離學生 pending 狀態不可轉入搜救清單」。但前端程式碼第 1474-1482 行及第 1557-1563 行，在 `!(pState === 'safe' || isDone)` 時直接執行 `gMissingTotal++` 與 `grandRescuing++`，並累加 `pulloutPendingOrMissing` 染紅班級卡片。這導致導師剛標註抽離、抽離老師尚未確認時，指揮官口頭報告立刻宣稱「搜救中」，製造假警報引發校園恐慌。
3. **並發點名時同步 Sheets I/O 拖垮 LockService（OPT-10 / ARCH-01 / BE-05，P0）**：
   全校 80+ 班導師在疏散至操場後 1~2 分鐘內密集送出點名。`updateClassReportDelta` 在持有 10 秒排隊鎖期間同步呼叫耗時 2.5 秒的試算表插入操作（`logAttendanceToSheet`）。第 5 位導師起必定突破 10 秒等待上限，拋出 Lock Timeout，導致 80% 以上導師點名失敗。
4. **PropertiesService 9KB 單值容量上限溢位（OPT-02 / ARCH-02 / BE-02，P0）**：
   Google Apps Script 的 ScriptProperties 單一 Property 值嚴格限制為 9,216 位元組。全校 80+ 班點名物件全數堆疊於 `CLASS_REPORTS_DATA`，當回報超過 30~40 班時 JSON 長度突破 10KB~15KB，GAS 將拋出不可捕捉之運行期崩潰，全校點名通報瞬間癱瘓。
5. **後端全域清空函式零鑑權與明文密碼（OPT-03 / SEC-01 / BE-03，P0）**：
   後端 `clearAllReports()` 完全未驗證呼叫者權限或密碼，前端雖有輸入 `8888` 提示，但任何人打開瀏覽器 F12 Console 即可呼叫 `google.script.run.clearAllReports()`，1 秒內惡意清空全校災情數據。

### OPT-01：`doGet()` 每次被訪問皆同步執行試算表清空、重寫、搬移分頁
- **面向分類**：效能與 Google 配額 (Performance & Google Quotas) / 災難現場可用性
- **程式碼位置**：`v204 Code.txt` 第 13-20 行、第 25-68 行
- **問題說明**：
  `doGet()` 是所有教職員透過手機開啟系統的首頁入口點。程式碼第 14 行直接呼叫了 `logVersionSummary()`。該函式每次被觸發時，均會對試算表執行 `moveActiveSheet(1)`、`sheet.clear()`、`sheet.getRange(...).setValues(...)` 以及兩次 `autoResizeColumn`！
  在地震疏散時，全校 70~100 位教職員會在 1 分鐘內密集開啟網頁，導致上百個 HTTP GET 請求同時爭搶同一份試算表進行清除與寫入，引發嚴重的 Sheets 寫入鎖衝突與執行超時（`Service Spreadsheets timed out`），使得前線導師在操場上連點名首頁都打不開（長達十幾秒白畫面或報錯崩潰）。版本歷史為靜態發布常數，絕不可在每次 GET 請求時動態覆寫。
- **優先級**：**P0**
- **影響程度**：極高。高並發開啟瞬間打垮 Google 試算表，造成全校教職員無法進入點名介面。
- **修改工作量**：S (< 1hr)
- **具體修正方式**：
  移除 `doGet()` 中的 `logVersionSummary()` 同步調用，改在管理員手動部署或版本號變更時單次執行。
  
  **BEFORE (`v204 Code.txt` 第 13-20 行)**：
  ```javascript
  function doGet() {
    logVersionSummary();
    return HtmlService.createTemplateFromFile('Index')
      .evaluate()
      .setTitle('清水國小 - 校園緊急點名與搜救通報系統')
      .addMetaTag('viewport', 'width=device-width, initial-scale=1.0, maximum-scale=1.0, user-scalable=no')
      .setXFrameOptionsMode(HtmlService.XFrameOptionsMode.ALLOWALL);
  }
  ```
  
  **AFTER**：
  ```javascript
  function doGet() {
    // 災難可用性防護：移除每次 GET 請求皆同步寫入試算表的高耗能操作，大幅提升高並發載入速度
    return HtmlService.createTemplateFromFile('Index')
      .evaluate()
      .setTitle('清水國小 - 校園緊急點名與搜救通報系統')
      .addMetaTag('viewport', 'width=device-width, initial-scale=1.0, maximum-scale=1.0, user-scalable=no')
      .setXFrameOptionsMode(HtmlService.XFrameOptionsMode.ALLOWALL);
  }
  ```
- **驗證方式**：
  使用多個瀏覽器無痕視窗同時開啟 Web App 網址，檢查 GAS 執行日誌，確認 `doGet` 執行時間由原先的 3500ms~6000ms 驟降至 200ms~400ms，無任何試算表寫入鎖衝突。

### OPT-02：PropertiesService 9KB 單一屬性容量上限溢位崩潰 (`CLASS_REPORTS_DATA`)
- **面向分類**：效能與 Google 配額 (Performance & Google Quotas) / 並發與資料一致性
- **程式碼位置**：`v204 Code.txt` 第 240-244 行、第 340 行、第 557 行
- **問題說明**：
  Google Apps Script 的 `PropertiesService`（ScriptProperties）具有硬性配額限制：**單一 Property 值的最大長度嚴格限制為 9,216 位元組 (9KB)**。若字串超過此上限，`setProperty()` 會直接拋出不可捕捉之致命異常：`Exception: The value for property 'CLASS_REPORTS_DATA' exceeds the maximum property size (9000 bytes)`。
  在現行程式碼中，全校 80+ 個班級（國小 6 個年級 65 班、幼兒園、14 個課後班、2 個學習扶助班及應變小組）的完整點名物件（包含實到、請假、抽離名單、失蹤名單及其地點標籤備註）全數序列化存放在單一鍵值 `CLASS_REPORTS_DATA`。當回報班級超過 30~40 班時，JSON 字串長度極易衝破 15KB~30KB。一旦溢位，後續所有導師點名送出時後端全面崩潰報錯，全校點名通報工作徹底中斷。
- **優先級**：**P0**
- **影響程度**：極高。演練或災難進行至中後段時系統必定全面癱瘓，資料無法再寫入。
- **修改工作量**：L (> 4hr)
- **具體修正方式**：
  實施年級分片儲存機制（Grade Sharding），將大字典分散為 `REPORTS_一`、`REPORTS_二` ... `REPORTS_課後班` 等獨立鍵值，並在資料載入時組合，徹底終結單一鍵值 9KB 配額炸彈。
  
  **BEFORE (`v204 Code.txt` 第 240-244 行)**：
  ```javascript
      var props = PropertiesService.getScriptProperties();
      var classReports = JSON.parse(props.getProperty("CLASS_REPORTS_DATA") || "{}");
      classReports[classKey] = singleReport;
      props.setProperty("CLASS_REPORTS_DATA", JSON.stringify(classReports));
  ```
  
  **AFTER**：
  ```javascript
      var props = PropertiesService.getScriptProperties();
      // 分片讀寫機制：依年級分散儲存，徹底防禦 9KB 單值容量上限
      var gName = singleReport.grade || classKey.split(" ")[0];
      var shardKey = "REPORTS_" + gName;
      var shardData = JSON.parse(props.getProperty(shardKey) || "{}");
      shardData[classKey] = singleReport;
      props.setProperty(shardKey, JSON.stringify(shardData));
      
      // 聚合全校回報物件（供前端回傳）
      var classReports = loadAllShardedReports(props);
  ```
- **驗證方式**：
  撰寫模擬測試寫入全校 80 個班級之點名資料，檢查 ScriptProperties 中各分片鍵值大小均在 2KB~4KB 之間，無任何 property size exceeded 例外發生。

### OPT-03：`clearAllReports` 後端零身分認證與前端密碼硬編碼明文
- **面向分類**：資安與個資 (Security & Privacy)
- **程式碼位置**：`v204 Code.txt` 第 355-362 行；`v204 Index.txt` 第 310 行、第 1374-1377 行
- **問題說明**：
  前端 `v204 Index.txt` 第 310 行明文宣告 `const ADMIN_RESET_PASSWORD = "8888";`，且重置資料函式 `resetAllDataWithPassword()` 僅在本地提示輸入密碼。
  然而，後端 `v204 Code.txt` 第 355 行的 `clearAllReports()` 函式卻完全是公開且零參數的 API！在 GAS 發布的 Web App 環境下，任何使用者（包含學生或惡意人士）只需開啟瀏覽器 F12 開發者工具 Console，輸入 `google.script.run.clearAllReports()`，後端便會在 1 秒內刪除全校所有的班級點名、搜救名冊、檢傷清單、家長聯繫與建物巡檢狀態！這是極為嚴重的客戶端安全防護失效漏洞（CWE-602）。
- **優先級**：**P0**
- **影響程度**：極高。任何具備基礎網頁知識者可隨意清空全校災難通報數據，造成不可逆破壞。
- **修改工作量**：S (< 1hr)
- **具體修正方式**：
  移除前端明文密碼常數；後端 `clearAllReports(authPassword)` 強制要求傳入授權密碼，並於後端進行身分核對，密碼不符者嚴格拒絕執行。
  
  **BEFORE (`v204 Code.txt` 第 355-362 行)**：
  ```javascript

      var props = PropertiesService.getScriptProperties();
      var keys = ["CLASS_REPORTS_DATA", "BUILDING_STATUS_DATA", "LAST_STRESS_TEST_CLASSES", "SEARCH_STATUS_MAP", "SEARCH_NOTES_MAP", "CONTACT_STATES", "HELP_REQUEST_MAP", "ASSIGNEE_MAP", "RESCUE_TRIAGE_MAP", "PULLOUT_STATUS_MAP", "VISITOR_COUNTS", "VISITOR_LIST_DATA", "APPROVED_CUSTOM_TOTAL", "SECURITY_MODE", "SIM_TIME_MODE"];
      keys.forEach(function(k) { props.deleteProperty(k); });
      return { success: true };
    } catch (e) { return { success: false, error: e.toString() }; }
  }
  ```
  
  **AFTER**：
  ```javascript
  function clearAllReports(authPassword) {
    try {
      var expectedPwd = PropertiesService.getScriptProperties().getProperty("ADMIN_AUTH_KEY") || "8888";
      if (!authPassword || String(authPassword).trim() !== expectedPwd) {
        Logger.log("資安警報：嘗試以無效密碼清空全校資料！");

      }
      var lock = LockService.getScriptLock();
      var hasLock = false;
      try {
        hasLock = lock.tryLock(5000);
        var props = PropertiesService.getScriptProperties();
        var keys = ["CLASS_REPORTS_DATA", "BUILDING_STATUS_DATA", "LAST_STRESS_TEST_CLASSES", "SEARCH_STATUS_MAP", "SEARCH_NOTES_MAP", "CONTACT_STATES", "HELP_REQUEST_MAP", "ASSIGNEE_MAP", "RESCUE_TRIAGE_MAP", "PULLOUT_STATUS_MAP", "VISITOR_COUNTS", "VISITOR_LIST_DATA", "APPROVED_CUSTOM_TOTAL", "SECURITY_MODE", "SIM_TIME_MODE"];
        keys.forEach(function(k) { props.deleteProperty(k); });
        return { success: true };
      } finally {
        if (hasLock) try { lock.releaseLock(); } catch(err) {}
      }
    } catch (e) { return { success: false, error: e.toString() }; }
  }
  ```
- **驗證方式**：
  在瀏覽器 Console 輸入 `google.script.run.withSuccessHandler(console.log).clearAllReports("wrong")`，確認回傳 `success: false` 且資料未被刪除；輸入正確密碼始可清空。

### OPT-04：使用者備註與訪客字串未轉義引發 DOM-based XSS 注入漏洞

- **影響程度**：中。壓測模擬不均勻，高年級無法演練搜救。
- **修改工作量**：S (< 1hr)
- **具體修正方式**：
  先洗牌在校班級清單再分配異常配額，並將實際生成數量動態寫入日誌。
- **驗證方式**：
  執行壓測後檢查，確認異常學生隨機分佈於各年級，日誌數據與實際相符。

### OPT-41：原生阻擋式 `prompt()` 與 `alert()` 可能遭行動瀏覽器封鎖導致流程中斷
- **面向分類**：可維護性 (Maintainability)
- **程式碼位置**：`v204 Index.txt` 第 464 行、第 474 行、第 1374 行、第 1722 行、第 1944 行
- **問題說明**：
  在 iOS Safari 與 Android Chrome 中頻繁彈出 `prompt()`，瀏覽器會主動跳出「禁止此頁面產生其他對話方塊」。一旦誤按，所有 `prompt()` 永遠回傳 null，導致指揮中心永遠無法輸入密碼解鎖或修改人數。且 `prompt()` 會凍結 JS 執行緒與背景輪詢。
- **優先級**：**P2**
- **影響程度**：高。遭瀏覽器安全機制封鎖導致業務流程中斷。
- **修改工作量**：M (1-4hr)
- **具體修正方式**：
  以頁面內建自訂非同步對話盒（Custom Modal）徹底替換原生 `prompt()`。
- **驗證方式**：
  多次快速切換指揮中心，確認自訂彈窗流暢展開，不被瀏覽器封鎖。

### OPT-42：訪客登記缺少輸入長度限制與型別白名單驗證防範惡意資料注入
- **面向分類**：資安與個資 (Security & Privacy)

- **影響程度**：中。潛在 DoS 儲存配額溢出風險。

- **驗證方式**：
  嘗試貼上萬字長文，確認被自動截斷至 50 字以內。

### OPT-43：全系統版本號與更新歷程仍停留在 V19.5 未對齊 V20.4
- **面向分類**：可維護性 (Maintainability) / 規格一致性
- **程式碼位置**：`v204 Code.txt` 第 3 行、第 40-48 行；`v204 Index.txt` 第 17 行；`v204 專案核心規格書.txt` 第 3 行
- **問題說明**：
  核心規格書明確記載當前系統版本為 **`V20.4 (發布代碼：204)`**。

- **優先級**：**P3**
- **影響程度**：低。版本標籤混亂，與規格書脫節。
- **修改工作量**：S (< 1hr)
- **具體修正方式**：
  更新註解並在 `versionHistory` 置頂補齊 V20.4 更新紀錄。
  
  **BEFORE (`v204 Code.txt` 第 3 行、第 40-43 行)**：

  ```javascript
      var versionHistory = [

  ```
  
  **AFTER**：
  ```javascript
   * 版本：V20.4 (發布版本號：204)
  ...
      var versionHistory = [
        { ver: "V20.4", summary: "架構核心升級：修正午餐時段12:40在校邊界、落實抽離待確認不誤計失蹤鐵律、補齊週四及手動時段排程、強化並發鎖與離線韌性。", deploy: 204 },
        { ver: "V19.5", summary: "全面優化分頁排序：日期檔置於版本摘要右方、點名與壓測日誌改為由新到舊置頂排列、清理冗餘分頁。", deploy: 195 },
  ```
- **驗證方式**：
  執行後檢視試算表「版本更新摘要」分頁第 2 列顯示為 V20.4 與發布代碼 204。

### OPT-44：缺少震動觸覺回饋與色盲友善雙重輔助圖示
- **面向分類**：災難現場可用性 (Disaster Field Usability)
- **程式碼位置**：`v204 Index.txt` 第 56-60 行、第 804-813 行
- **問題說明**：
  災難現場導師眼睛時刻顧及學童走動，難以一直盯著螢幕確認點選。缺少觸覺震動常造成不確定感而重複點擊。此外，紅綠色弱教師難以僅靠顏色區分實到（綠）與失蹤（紅）。
- **優先級**：**P3**
- **影響程度**：中。無障礙體驗與感官反饋不足。
- **修改工作量**：S (< 1hr)
- **具體修正方式**：
  在狀態切換時調用 `navigator.vibrate(35)`；在紅色失蹤卡片加上雙線邊框與 ⚠️ 圖示達成形狀與色彩雙重辨識。
  
  **BEFORE (`v204 Index.txt` 第 812 行)**：
  ```javascript
  renderMatrix(); triggerAutoSaveTimer();
  ```
  
  **AFTER**：
  ```javascript
  renderMatrix(); triggerAutoSaveTimer();
  if (navigator.vibrate) navigator.vibrate(35); // 觸覺反饋
  ```
- **驗證方式**：
  在支援震動的手機點擊卡片感受短震動，確認失蹤卡片具備形狀辨識輔助。

### OPT-45：1967 行單一檔案內散落 30+ 個未命名空間之全域變數 (Spaghetti State)
- **面向分類**：可維護性 (Maintainability)
- **程式碼位置**：`v204 Index.txt` 第 250-280 行
- **問題說明**：
  `v204 Index.txt` 存在 30 多個變數直接宣告在全域 `window` 範疇（`allStudents`, `currentClassStudents`, `studentStatusMap`, `classReports`...）。各函式任意交互讀寫，形成高度耦合的義大利麵狀態，維護時極易產生難以追查的副作用。
- **優先級**：**P3**
- **影響程度**：中。架構混亂增加後續維護除錯難度。
- **修改工作量**：M (1-4hr)
- **具體修正方式**：
  宣告單一全域命名空間物件 `const AppState = { ... };` 集中管理狀態。
  
  **BEFORE (`v204 Index.txt` 第 250-260 行)**：
  ```javascript
  let allStudents = [];
  let currentClassStudents = [];
  let studentStatusMap = {}; 
  let classReports = {};
  ```
  
  **AFTER**：
  ```javascript
  const AppState = {
    allStudents: [],
    currentClassStudents: [],
    studentStatusMap: {},
    classReports: {},
    contactStates: {},
    searchStatusMap: {},
    rescueTriageMap: {},
    pulloutStatusMap: {}
  };
  ```
- **驗證方式**：
  狀態集中後確認各看板雙向綁定正常，全域變數乾淨受控。
